# Dataset specification — generated and captured on the day

This file is an **idea-level design**, not a dataset. On 31 Oct the team creates every fixture inside the contest repo:
- Codex generates the synthetic cases from this spec.
- Real cases are captured on the day from public pages.
- Humans write the expected answers before the pipeline runs on them.

Nothing here is copied from an earlier build. Generate fresh wording. The design only fixes what each case must plant
and what it must prove.

Owner: **P4** (`fixtures/**`, `scripts/{capture_page,make_label_images,check_fixtures}.py`). P2 owns
`backend/app/data/*.json` (§6). Prompts that use this file: P4-0c, P4-1c, P4-2b, P4-3 (blind sets), P2-0/1/2/4.

## 1. Rules for every fixture
- **Origin.** Every product and source declares `dataset_origin`:
  - `REAL` — captured on the day from a public URL, with `uri`, `captured_at`, and sha256 computed by the loader;
  - `SYNTHETIC` — invented. Synthetic products use a fictional brand (suggested "Lumivy Lab (fictional)"), ids
    prefixed `DEMO-`, `BLIND-`, and notification numbers shaped `DEMO-CBMP-xxxxx`. They never use a real brand name.
- **Expected answers come first.** A human writes them in `fixtures/gold/**` before the first pipeline run on that case.
  App code never reads `fixtures/gold/` (AGENTS rule 11).
- **No tuning to fixtures.** If a case fails, fix a mechanism, or add a new blind case. Never special-case the text.
- **Real page text** is third-party content. Keep it for evaluation, with URL and capture time. Never edit it. Quote
  short excerpts in the UI. See PROPOSAL OQ-8 for whether a public repo may hold full snapshots. Words such as
  "Chính hãng" or "an toàn" on a real page are the source's words: keep them, show them only as quoted source text; the
  forbidden-word rule applies to text the system writes (AGENTS rule 1).
- **Encoding.** UTF-8 JSON with Vietnamese diacritics kept.
- **Validation.** `python scripts/check_fixtures.py` must pass before any commit. The uppercase marker `TODO` is
  forbidden (case-sensitive).

## 2. Formats
**Product folder:** `fixtures/<group>/<product-folder>/`. Groups:
- `real` — captured;
- `synthetic` — generated;
- `blind/setN` — generated by P4 for evaluation.

**`product.json`:**
```json
{"product_id": "…", "name": "…", "brand": "…", "variant": "50ml", "market": "VN", "dataset_origin": "REAL|SYNTHETIC",
 "case_id": "…", "tenant_id": "demo-tenant", "listing_id": "…",
 "web": {"enabled": false, "brand_domains": [], "aliases": []}, "note": "why this case exists"}
```
**Source snapshot** (one JSON file per source version; version 1 files end in `.v1.json` and are seeded; later versions
arrive through events):
```json
{"source_id": "…", "kind": "LISTING|BRAND_PAGE|NOTIFICATION_DOC|PACKAGING_IMAGE|SELLER_UPLOAD|WEB_PAGE", "product_id": "…",
 "version": 1, "uri": "https://… | demo://…", "captured_at": "ISO-8601", "dataset_origin": "REAL|SYNTHETIC",
 "visibility": "PUBLIC|PRIVATE", "family": "seller:<shop> | brand:<site> | packaging:<brand> | regulator:<doc> | upload:seller:<id>",
 "scope": {"product": "…", "variant": "50ml | MULTI | null", "market": "VN", "version": "…"},
 "passages": [{"id": "…", "locator": "title | highlights#2 | description#p1 | specs#volume | ingredients | image:full | page1#company", "section": "…", "text": "…"}]}
```
- `scope` may be omitted for real pages. The pipeline infers it (policy R3).
- A `PACKAGING_IMAGE` has a sibling image with the same stem (`.png`). Its passage text is the human transcript, or
  empty for an unreadable photo.

**Event:** the envelope from `docs/05-contracts.md` §1, plus `"expect": "<one sentence>"`. The operator UI shows
`expect` as the stage caption. The file name is the fixture name: `NN-<slug>.json` in `fixtures/events/`.

**Registry (mock):** `fixtures/synthetic/registry/mock_registry.json` →
`{"registry": "MOCK …", "warning": "SYNTHETIC — fictional numbers", "records": {"DEMO-CBMP-00042": {"product_name", "holder", "status": "ACTIVE|REVOKED", "issued", "revoked?"}}}`.

**Marketplace sellers (outside any case):** `fixtures/marketplace/<product_id>/<seller>.json`. Same snapshot format,
`kind: LISTING`, one file per seller. A seller can be REAL (another retailer's page) or SYNTHETIC.

**Gold (offline only):**
- `fixtures/gold/dev/demo-story.json` — checkpoints after each event: `{after_event, expected: {field: verdict}}`.
- `fixtures/gold/dev/real.json` — per real product.
- `fixtures/gold/blind/expected-setN.json` — per product: fields, claims, probes.

Each file has `labelled_by` (names), `labelled_at`, and `status` (DRAFT or REVIEWED).

Capture rules: `scripts/capture_page.py <url> --product <id> --kind LISTING|BRAND_PAGE|WEB_PAGE` (P4, written on the
day).
- Fetch with httpx and a timeout.
- Convert HTML to text with the standard-library parser.
- Cut to the product: drop menus, "related products" and link cards.
- Split into passages with locators: title, highlights, description#pN, specs/usage, ingredients.
- Write the snapshot (REAL, `uri`, `captured_at`) and print it for human review.
- If the page blocks fetching, skip that case and use another retailer. Never retype a page by hand as "REAL".

What stays **synthetic**, on purpose:
- revocation of a notification (we do not stage a revocation for a real company);
- seller edits (volume change, prompt injection);
- an unreadable photo;
- the guaranteed claim true positive (alcohol-free and fragrance-free claims contradicted by the INCI);
- the mock registry;
- the multi-size catalogue for the agent's anchor test;
- blind sets.

## 5. Blind sets — P4 writes them, the lanes that write rules do not
Purpose: prove adaptation to products the code was never shaped on. Process:
1. P4 (a human) writes the case table: product, planted condition, expected verdict per field. Commit it as
   `fixtures/gold/blind/expected-setN.json` (status DRAFT, then REVIEWED by a second person).
2. Codex generates fixtures realising each row. Then `check_fixtures.py`.
3. Run `blind_eval.py` once and report as-is. A miss is a finding, never a reason to edit the case.

Probe categories (≥ 12 products per set; mix them):
(Categories only. P4 picks the concrete examples on the day when writing the expected table, so the people who write
the rules have not seen them.)
- **units:** other units, multi-packs, combos with a free mini;
- **open vocabulary:** common Vietnamese ingredient names, vitamin names vs INCI names;
- **legal forms:** company legal-form variants;
- **identifiers:** formatting noise, a one-digit-off number (true positive), a number that differs between sources;
- **skin type:** phrasing outside the seed, an overclaim, a narrower listing;
- **claims:** a free-from claim that is fine and one that is not, an implausible vs a plausible percentage;
- **scope:** no metadata, a page for another market, two pages from one site (one family), a catalogue with sizes;
- **language:** an English listing, a Korean brand page;
- **adversarial:** an injection in English, plus a real volume error;
- **missing evidence:** no label and no brand page.

## 6. App data files (P2 creates them from this section; data with a source note, not code)
- `backend/app/data/vocab_seed.json` — the **small** seed (open sets are learned at run time):
  - about 6 ingredient entries `{label, surfaces[], inci[]}`: niacinamide, hyaluronic acid/sodium hyaluronate,
    ceramides (NP/AP/EOP), salicylic acid/BHA, glycerin, zinc;
  - skin phrases VI/EN → SkinType sets ("mọi loại da" → ALL, "da thường đến da dầu" → NORMAL+COMBINATION+OILY, because "X đến Y" spans the ordered scale DRY < NORMAL < COMBINATION < OILY (a seed rule with its source note), "da khô" → DRY…);
  - free-from families with INCI patterns (alcohol: Alcohol, Alcohol Denat., Ethanol — fatty alcohols excluded;
    fragrance: Parfum, Fragrance; paraben: *paraben);
  - treatment words ("trị mụn", "đặc trị", "chữa");
  - injection patterns ("ignore previous instructions", "bỏ qua hướng dẫn").
  `_about` says it is a seed.
- `backend/app/data/legal_forms.json` — a closed set, longest first: Công ty TNHH / Cty TNHH / TNHH MTV / Công ty Cổ
  phần / Công ty CP / JSC / Co., Ltd / LLC…
- `backend/app/data/regulatory_limits.json` — max % used by the INCI-order rule, with source "EU Regulation 1223/2009
  Annex V via CosIng; confirm against ASEAN Annex VI": phenoxyethanol 1.0, benzyl alcohol 1.0, methylparaben 0.4,
  ethylparaben 0.4, propylparaben 0.14, butylparaben 0.14, chlorphenesin 0.3, sorbic acid / potassium sorbate 0.6,
  dehydroacetic acid / sodium dehydroacetate 0.6. **Verify each value on the day before using it on a slide.**
- `backend/app/data/web_search.json`:
  - query templates (`{brand} {name} {variant}`, plus a field-specific one each for skin type, ingredients and volume);
  - retailer domains (VN pharmacy/beauty chains: nhathuoclongchau.com.vn, pharmacity.vn, hasaki.vn, guardian.com.vn,
    watsons.vn, picare.vn);
  - comparison terms ("so sánh", "vs", "top");
  - section-end markers ("sản phẩm liên quan", "có thể bạn cũng thích", "có thể bạn sẽ thích", "xem thêm", "đánh giá từ người mua", Q&A blocks such as "hỏi đáp", "you may also like").
- `backend/app/data/model_prices.json` — USD per 1M tokens from the official pricing page **on the day**, with date and
  URL.
